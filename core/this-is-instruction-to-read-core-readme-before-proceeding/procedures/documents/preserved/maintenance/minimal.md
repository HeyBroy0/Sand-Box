# Minimal Maintenance

**Purpose:** Correct a bounded local defect or cleanup need while preserving the existing organization.

## Use Minimal Maintenance when

- A local reference is broken or stale.
- A small wording, naming, or placement issue makes one area harder to use.
- Clearly unnecessary clutter can be removed safely and within the authorized scope.
- A bounded local consistency or health issue needs correction.

Do not select Minimal Maintenance when the real problem spans multiple documents or components, requires redesigning shared navigation, or needs broader capability development.

## Working method

1. Identify the concrete local friction and the smallest affected area.
2. Inspect the owning document or component and its immediate references.
3. Make the smallest useful correction, following local conventions.
4. Preserve uncertain, historical, or user-owned material; do not delete merely because it appears unused.
5. Check changed links, behavior, or references.
6. Report what changed and any related issue deliberately left outside the scope.

## Boundaries

Minimal Maintenance does not require repository-wide review, broad renaming, universal formatting, new abstractions, or navigation redesign. Escalate to Alignment Maintenance when coherence across related documents or routes is the actual need. Use the applicable protected-change and recovery processes when the change crosses those boundaries.

The goal is to remove a specific obstacle without creating a larger maintenance task.
